# WiFi Installation Billing & Collection System — Architecture Plan

Offline-first web application for managing WiFi installation customers, billing, and
payment collection. Built with Next.js (App Router) and runs fully in the browser as a
PWA with a local SQLite database — works with no internet connection.

---

## 1. Goals

| Goal | Approach |
|---|---|
| Installable PWA (phone + desktop) | Web App Manifest + service worker, `display: standalone` |
| Works fully offline | Client-side SQLite (sql.js/WASM) persisted to IndexedDB |
| Billing & collections workflow | Installations → monthly invoices → payments → arrears tracking |
| Single-operator friendly (no backend) | All data local; export/import JSON + SQL backup; optional CSV export |
| Simple, usable UI | Tailwind, mobile-first layout, bottom nav on small screens |

Non-goals (v1): multi-user auth/server sync, SMS/email sending, payment gateway integration.
These are extension points (see §9).

---

## 2. Tech Stack

| Layer | Choice | Why |
|---|---|---|
| Framework | Next.js 16 (App Router, TypeScript) | Requested; static export for easy hosting |
| UI | React 19 + Tailwind CSS 4 | Fast to build, consistent styling |
| Database | SQLite via **sql.js** (WebAssembly) | Real SQL in the browser, no server; typed query wrapper on top |
| Persistence | **IndexedDB** (single blob row) | Durable storage of the SQLite file; auto-save after writes |
| PWA | Hand-rolled `manifest.webmanifest` + `sw.js` | Small, auditable, no extra runtime dependency |
| Icons | Static PNGs generated by a Node script | Reproducible, no binary assets in git history to manage |
| Export | JSON (full backup) + CSV (per table) | Easy for non-technical operators |

**Why sql.js and not Wa-SQLite/OPFS?** sql.js is pure WASM, works on every browser
(including older Android WebViews), and needs no special storage APIs. Persistence is a
single `Uint8Array` dump — simple and easy to back up. If concurrency ever matters, the
DB layer is isolated behind `src/lib/db/*` so the engine can be swapped.

## 4. Data Model (SQLite)

All money amounts are **integers in the smallest unit** (e.g., centavos) to avoid
floating-point drift. Dates are ISO `TEXT`.

```sql
-- Customers ------------------------------------------------------------
CREATE TABLE customers (
  id            TEXT PRIMARY KEY,          -- UUID
  full_name     TEXT NOT NULL,
  phone         TEXT NOT NULL,
  address       TEXT NOT NULL,
  plan_id       TEXT REFERENCES plans(id),
  status        TEXT NOT NULL DEFAULT 'active',   -- active | inactive
  created_at    TEXT NOT NULL
);

-- Plans ----------------------------------------------------------------
CREATE TABLE plans (
  id            TEXT PRIMARY KEY,
  name          TEXT NOT NULL,             -- e.g. "Home 25 Mbps"
  monthly_price INTEGER NOT NULL,          -- smallest currency unit
  speed_mbps    INTEGER NOT NULL,
  active        INTEGER NOT NULL DEFAULT 1
);

-- Installations (job tickets) -------------------------------------------
CREATE TABLE installations (
  id              TEXT PRIMARY KEY,
  customer_id     TEXT NOT NULL REFERENCES customers(id),
  scheduled_date  TEXT,
  completed_date  TEXT,
  installer       TEXT,
  status          TEXT NOT NULL DEFAULT 'scheduled', -- scheduled|in_progress|completed|cancelled
  installation_fee INTEGER NOT NULL DEFAULT 0,       -- charged once
  notes           TEXT,
  created_at      TEXT NOT NULL
);

-- Invoices ---------------------------------------------------------------
CREATE TABLE invoices (
  id            TEXT PRIMARY KEY,
  customer_id   TEXT NOT NULL REFERENCES customers(id),
  period_start  TEXT NOT NULL,             -- first day of month
  period_end    TEXT NOT NULL,
  amount        INTEGER NOT NULL,          -- monthly charge
  type          TEXT NOT NULL DEFAULT 'monthly',  -- monthly | installation
  status        TEXT NOT NULL DEFAULT 'unpaid',   -- unpaid | partial | paid | void
  due_date      TEXT NOT NULL,
  created_at    TEXT NOT NULL,
  UNIQUE(customer_id, period_start, type)
);

-- Payments ----------------------------------------------------------------
CREATE TABLE payments (
  id          TEXT PRIMARY KEY,
  invoice_id  TEXT NOT NULL REFERENCES invoices(id),
  amount      INTEGER NOT NULL,            -- applied amount
  method      TEXT NOT NULL DEFAULT 'cash',-- cash | gcash | bank | other
  paid_at     TEXT NOT NULL,
  reference   TEXT,                        -- receipt no / txn ref
  notes       TEXT,
  created_at  TEXT NOT NULL
);

CREATE INDEX idx_invoices_customer ON invoices(customer_id);
CREATE INDEX idx_invoices_status   ON invoices(status);
CREATE INDEX idx_payments_invoice  ON payments(invoice_id);
```

**Derived figures** (computed in SQL views/queries, not stored):
- Invoice balance = `amount − SUM(payments.amount)`
- Customer arrears = sum of unpaid invoice balances
- Collection rate = collected ÷ invoiced for a period

## 5. Offline & Persistence Strategy

```
┌──────────────┐   exec()   ┌────────────────┐  dump()   ┌───────────────┐
│  UI (React)  │◄──────────►│  db layer      │──────────►│ IndexedDB     │
│  pages       │  typed     │  (sql.js WASM) │ autosave  │ key: appdb    │
└──────────────┘  queries   └────────────────┘ (debounced)└───────────────┘
```

1. On app start, `DataProvider` initializes the DB: loads WASM, reads the saved
   `Uint8Array` from IndexedDB (or creates a fresh DB + runs schema/migrations).
2. Every write goes through `repository.ts`; after a write the DB is dumped and
   persisted to IndexedDB (debounced ~300ms).
3. `beforeunload`/`visibilitychange` flush pending saves.
4. A **"Download backup (.json)"** button in Settings gives the user a portable copy;
   "Restore" re-imports it. CSV export per table for spreadsheets.

### Service worker (`sw.js`)
- **Precache:** app shell (`/`, `/offline`), manifest, icons.
- **Runtime:** cache-first for `/_next/static/*` and icons; **network-first with cache
  fallback** for navigations (falls back to `/offline` when both fail).
- All app pages are client-rendered ("use client" pages under the shell), so once the
  shell + chunks are cached, the whole app runs offline.
- Versioned cache names + old-cache cleanup on `activate`.

## 6. UI / Routes

| Route | Purpose |
|---|---|
| `/` | Dashboard: MRR, collected this month, outstanding balance, active installs, recent payments |
| `/customers` | List, search, add/edit modal, deactivate |
| `/installations` | Job tickets: schedule → in progress → completed (auto-creates installation invoice) |
| `/billing` | Invoice list w/ filters; **Generate invoices** for a month (batch, idempotent); mark void |
| `/payments` | Record payments (partial allowed); payment updates invoice status; receipt view |
| `/settings` | Backup/restore JSON, CSV export, seed demo data, wipe DB |
| `/offline` | Static fallback page |

Global shell: sidebar on ≥md, bottom tab bar on mobile, online/offline indicator in header.

## 7. Build & Config

- `next.config.ts`: `output: "export"` (static export — deployable to any static host),
  headers are not available on export so SW cache headers are unnecessary (same-origin).
- TypeScript strict mode. ESLint (next config). No server actions/API routes (offline app).
- Scripts: `dev`, `build`, `start`, `lint`, `icons` (regenerate PWA icons).

## 8. Testing / Verification

- `tsc --noEmit` type check.
- `next build` (static export) must pass.
- Manual smoke checklist: add customer → schedule install → complete → generate
  invoices → record partial payment → check dashboard numbers → reload offline (airplane
  mode) → app still loads with data intact.

## 9. Extension Points (future)

- **Sync:** add a server API + `synced_at` columns; repository layer is the single write path.
- **Auth:** NextAuth/Auth.js on the hosted version.
- **SMS reminders:** webhook into arrears query.
- **Multiple DB engines:** swap `lib/db/database.ts` (e.g., wa-sqlite + OPFS) without
  touching repositories.
